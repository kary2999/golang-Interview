# Golang Interview Sprint Companion 打卡伙伴 UI 设计

## 1. 背景与决策效力

当前应用已经实现 B1「单卡快刷」：用户揭晓答案后完成“不会 / 模糊 / 掌握”三级自评，获得 XP，进入下一题，并通过本机 `localStorage` 保存训练、待复习和活动日数据。应用保持纯 HTML、CSS、JavaScript，支持 `file://` 直接打开及 HTTPS / localhost PWA 两条运行路径。

本设计采用已批准的 A 方向「Sprint Companion · 冲刺伙伴」。题目卡仍是唯一主要工作区；吉祥物、今日打卡、日历和错题本只增强陪伴与复盘，不把应用改造成仪表盘或多页面产品。

本文件补充并局部替代 `2026-08-09-daily-sprint-ui-design.md`：

- 每个浏览器本地自然日必须完成 **20 道不同题目的自评**，该日才算打卡成功并具有连续学习资格。
- 旧设计中的“每天累计 10 次自评”规则失效。
- 不会、模糊、掌握仍分别获得 2 / 8 / 20 XP；复习调度仍分别为 7 次后、20 次后和移出待复习。
- 其他 B1 单卡、题序、导航、来源、PWA、离线和导入导出约束继续有效。

## 2. 术语与产品不变量

- **本地日**：发生自评时，浏览器系统时区解释出的公历日期，键格式为 `YYYY-MM-DD`。
- **有效自评**：用户已揭晓答案并选择“不会”“模糊”或“掌握”之一。
- **当日不同题数**：该本地日所有有效自评对应题目 ID 的去重数量。
- **打卡成功**：当日不同题数达到 20。第 20 道之后继续训练不会重复结算打卡或连续天数。
- **错题本**：由每题最近一次自评派生出的当前薄弱题集合。
- **待复习成员**：`hardIds` 中可在现有“待复习”模式浏览的题目。
- **复习队列**：`reviewQueue` 中按全局累计自评次数安排再次出现时机的调度记录。

以下规则不可被视觉实现改变：

1. 三种自评均可贡献当日不同题数。
2. 同一题同一天无论自评多少次，打卡进度最多贡献 1。
3. 揭晓、收起答案、跳过、前后导航、重新洗牌和按 `J` 手动切换待复习均不贡献打卡进度。
4. 重复题仍照常结算 XP、题目统计和复习调度；只有打卡去重。
5. 随机刷题与待复习模式中的有效自评都参与同一个本地日打卡集合。
6. 题目 ID 是去重身份；题目文字、索引位置和展示顺序不是身份。

## 3. 目标与非目标

### 3.1 目标

- 在不破坏 B1 单卡专注的前提下，让用户随时看清今日 `0 / 20` 至 `20 / 20` 的进度。
- 用普通、焦虑、抓狂三种应用内吉祥物状态表达时间紧迫度，但不施加失败惩罚。
- 达到 `20 / 20` 时立即给予稳定、可访问的成功反馈。
- 提供当前月打卡日历，并可在保留的活动历史范围内切换月份。
- 提供自动维护的错题本，并复用现有待复习训练路径。
- 以可验证的每日题目 ID 集合支撑“20 道不同题”规则。
- 保持本地优先、零运行时远程依赖、可导出和可离线。

### 3.2 非目标

- 不新增账号、后端、数据库、云同步、遥测、排行榜或跨设备自动合并。
- 不新增主导航页面、路由或训练配置流程。
- 不修改 XP 数值、等级规则、基础题序或 7 / 20 次复习间隔。
- 不增加错题自由文本、标签、手动笔记、归档或“曾经错过”的永久事件历史。
- 不修改题目正文、答案、`promptHtml`、来源或生成数据。
- 不修改 PWA 安装图标，也不做按心情变化的系统图标、角标或通知。
- 不引入外部吉祥物素材、远程图片、字体、框架或构建工具。
- 不解决系统时钟恶意篡改；只定义可预测、单调的降级行为。

## 4. 信息架构与布局

### 4.1 保留单卡主层级

页面自上而下保持：

1. 紧凑应用头部。
2. 学习状态条。
3. 非阻断通知。
4. 唯一主要题目卡。
5. 现有辅助操作。
6. 按需打开的二级对话框。

日历和错题本不得常驻题目卡两侧，不新增首页数据墙，不把题目推到首屏以下。桌面和移动端都应先看到当前题目与当前阶段的主要操作。

### 4.2 头部

- 将当前应用内 `GO` 品牌块替换为紧凑的 Sprint Companion 吉祥物及品牌文字。
- 吉祥物属于网页内容，只在 `index.html` / `assets/styles.css` 中渲染。
- 保留“随机刷题”“待复习”“成就”、安装入口和进度管理。
- 将现有禁用的“分类即将上线”槽位替换为可操作的“学习记录”按钮。
- “学习记录”打开一个二级对话框，内含“打卡日历”和“错题本”两个面板；不在头部再增加两个并列按钮。
- “学习记录”不是训练模式，不使用 `aria-pressed` 与随机 / 待复习竞争。

### 4.3 学习状态条

现有状态条继续显示连续学习、等级 XP、今日进度和连续掌握，其中“今日训练 N 题”改为“今日打卡 N / 20”：

- `N = min(当日不同题数, 20)`。
- 同时提供紧凑进度条，语义为 `role="progressbar"`、`aria-valuemin="0"`、`aria-valuemax="20"`、`aria-valuenow=N`。
- 未完成时，辅助文案为“完成自评的不同题”；完成后改为“今日打卡成功”。
- 进度条与数字不能只靠颜色表达状态。
- 第 20 道之后界面保持 `20 / 20`，实际活动桶仍可保存更多不同题 ID。

### 4.4 学习记录对话框

“学习记录”使用现有对话框样式和打开 / 关闭基础设施：

- 初次打开默认显示“打卡日历”。
- 两个面板使用可聚焦的标签按钮；标签具备 `role="tab"`、`aria-selected`、`aria-controls`，面板具备 `role="tabpanel"`。
- 标签采用自动激活：左右方向键同时移动焦点并切换面板，Home / End 同时聚焦并激活首尾标签。
- `Escape` 或关闭按钮关闭；关闭后焦点回到“学习记录”触发按钮。
- 不支持原生 `<dialog>` 时，退化为页面内受控面板：打开后焦点进入标题，关闭时恢复触发点，不能因降级丢失内容或操作。

## 5. 吉祥物与本地时间契约

### 5.1 三个应用内状态

必须提供同一个 Sprint Companion 的三个本地渲染状态：

1. **普通 `normal`**：基础黄色 / 品牌色外形，放松眼睛和微笑嘴形。
2. **焦虑 `anxious`**：保持同一轮廓和布局尺寸，以眉眼、嘴形和汗滴等局部变化表达焦虑。
3. **抓狂 `frantic`**：保持同一轮廓和布局尺寸，以紧张眼形、张嘴或轻微倾斜表达抓狂。

实现使用同一段语义化吉祥物标记和三个 CSS 状态类，不新增外部素材或运行时资源。三个状态必须：

- 共享尺寸、基线和轮廓，切换时不引发布局跳动。
- 除颜色外还具有脸部几何差异，并配有可见状态文字。
- 在状态文字已经完整表达含义时将图形标记为 `aria-hidden="true"`，避免读屏重复。
- CSS 状态类缺失时回退到普通外形，文字仍说明当前状态。

### 5.2 时间边界

当今日尚未打卡成功时，心情按浏览器当前本地时间的左闭右开区间派生：

- `00:00:00 <= 本地时间 < 15:00:00`：普通。
- `15:00:00 <= 本地时间 < 21:00:00`：焦虑。
- `21:00:00 <= 本地时间 < 次日 00:00:00`：抓狂。

因此：

- 恰好 15:00 进入焦虑。
- 恰好 21:00 进入抓狂。
- 恰好次日 00:00 进入新本地日，进度从新日活动桶读取，未完成时为普通。

### 5.3 完成覆盖与刷新时机

- 当第 20 个不同题 ID 写入当日活动桶后，本次状态事务内立即派生为已完成。
- 不等待 300ms 自动切题结束，头部吉祥物立即恢复普通状态，并显示固定成功文案“今日打卡成功”。
- 完成状态保持到该本地日结束；当天后续时间即使进入 15:00 或 21:00，也不再显示焦虑或抓狂。
- 心情不写入 `localStorage`、导出文件或题目统计。
- 页面启动、每次渲染、自评完成、窗口重新获得焦点及 `visibilitychange` 回到可见时都重新读取当前时间。
- 页面可见时只安排到下一个 15:00、21:00 或本地午夜的单次计时器；触发后根据真实 `Date` 重算并安排下一次，不通过累加小时推测时间。
- 浏览器后台冻结计时器时不要求准点执行；回到前台时必须立即纠正。

### 5.4 固定安装图标

PWA 的 `manifest.webmanifest` 图标、Apple Touch Icon、`assets/icons/app-icon.svg` 源和现有 192 / 512 / maskable PNG 保持不变：

- 系统桌面、Dock、任务切换器和主屏幕始终使用当前固定 `GO` 闪电图标。
- 普通、焦虑和抓狂只影响应用页面内的吉祥物 / Logo。
- 不按时间改写 manifest，不动态生成图标，不增加远程图标地址。

## 6. 自评、反馈与打卡状态转换

### 6.1 单次自评事务

用户点击评级或按 `1 / 2 / 3` 时，只读取一次当前时间，并在同一个新状态中完成：

1. 校验答案已揭晓、当前题存在且未处于转场。
2. 按现有规则结算 XP、连续掌握、题目统计、`hardIds` 和 `reviewQueue`。
3. 用同一个时间快照取得 `localDay`。
4. 增加该日 `ratingCount`，并把当前题目 ID 合并到 `ratedQuestionIds` 去重集合。
5. 判断是否由 `< 20` 首次跨到 `>= 20`。
6. 一次性替换内存状态并尝试一次持久化。
7. 同步渲染评级反馈、打卡进度、吉祥物和成功文案。
8. 按现有短暂停留规则进入下一题。

这样可避免 23:59:59 点击后，XP 记入前一天而打卡 ID 记入后一天。

### 6.2 评级主文案

评级反馈的第一视觉层级必须使用以下固定文案：

- 掌握：`已掌握，干得漂亮`
- 模糊：`加油，已经很棒了`
- 不会：`没关系，继续努力`

XP 和调度信息放在较小的第二层：

- 掌握：`+20 XP · 已移出待复习`
- 模糊：`+8 XP · 20 次后复习`
- 不会：`+2 XP · 7 次后复习`

等级提升和打卡成功可追加为第三段状态，不得替换主鼓励文案。第 20 道的完整可访问播报示例为：

`已掌握，干得漂亮。获得 20 XP。今日打卡成功，20 / 20。`

### 6.3 自动下一题与读屏

- 非 reduced-motion 环境继续保留当前约 300ms 的非阻断反馈停留。
- 转场期间禁用会造成重复结算的评级与题目导航。
- `prefers-reduced-motion: reduce` 时取消视觉等待并立即进入下一题。
- 可见 `#rating-feedback` 只承载视觉文案，不设置直播语义；现有全局 `#live-region` 是本次评级唯一的 `aria-live="polite"` 播报源，避免屏幕阅读器重复朗读。
- reduced-motion 即使立即换题，全局直播区仍保留完整鼓励、XP 和打卡状态播报。
- 自动前进后焦点回到新题标题；不能落在已隐藏的评级按钮。

## 7. 打卡日历

### 7.1 月视图与导航

- 默认显示浏览器当前本地年月，标题格式为“YYYY 年 M 月”。
- 周标题固定为周一至周日。
- “上个月”“下个月”使用原生按钮并提供包含目标月份的无障碍名称。
- 可导航最早月份为当前保留活动桶中的最早 `localDay` 所在月。
- 可导航最晚月份为当前本地月与保留活动桶最晚月份中的较晚者；这允许查看系统时钟回拨后暂时落在“未来”的已记录活动。
- 没有活动数据时只显示当前月，并禁用两个越界方向。
- 月份切换只重绘日历，不改变训练状态、当前题或页面 URL。

### 7.2 日期状态

每个日期格显示日期数字和文本 / 图形标记，状态按以下规则派生：

- **已打卡**：存在活动桶且 `ratedQuestionIds.length >= 20`。
- **部分完成**：存在活动桶但未满足已打卡；显示 `N / 20`。迁移自 v2 且无法证明不同题数的记录显示“有训练，未验证”，不能显示勾选。
- **错过**：日期早于当前本地日、位于可证明的保留历史范围内，且没有活动桶。
- **未来**：日期晚于当前本地日且没有活动桶；使用弱化样式，不显示失败语义。
- **今天**：日期等于当前本地日，使用 `aria-current="date"` 和独立描边；“今天”是覆盖标记，底层仍可同时是 `0 / 20`、部分完成或已打卡。

今天没有活动桶时明确显示“今天 · 0 / 20”，不显示“无数据”或“错过”。

状态优先级为：

1. 有活动桶时先显示已打卡或部分完成。
2. 再叠加“今天”标记。
3. 只有无活动桶时才在错过、未来或中性无数据中三选一。

系统回拨造成某个已记录日期晚于当前日期时，该格仍显示其已打卡或部分完成状态，并在可访问名称中追加“设备日期当前早于该记录”；不能把真实记录覆盖成空白未来格。

### 7.3 可证明历史范围

`activityDays` 只记录至少发生过一次有效自评的本地日，因此“没有桶”不总能证明用户当时错过：

- 从最早保留活动桶到今天之间的空白过去日期可标为“错过”。
- 早于最早保留桶的日期显示中性“无数据”，不得伪装成错过。
- 400 个活动桶裁剪后，裁剪范围之外同样显示“无数据”。
- 日历不提供日期详情页，也不允许通过点击日期改写状态。

### 7.4 时区变化、旅行与时钟回拨

- 自评发生时把当时的本地日期字符串固化为 `localDay`；之后切换时区不会重新解释或搬移历史桶。
- 旅行到本地日期更早的时区时，新自评合并到该日期已有桶，或创建该日期桶。
- 旅行到本地日期更晚的时区时，新自评写入新日期；跨过的空白日期可在历史范围内显示为错过。
- 设备日期回拨不会减少 XP、删除活动桶、降低已保存的最长连续天数或回退 `profile.lastPracticeAt`。
- 某个日期从未达标到达标时，仅当该 `localDay` 晚于当前最大已达标日期，才更新连续学习计数。
- 对最大已达标日期相同或更早的回拨 / 补录不重复增加连续天数，也不追溯修补已断开的连续记录。
- 日期向前跳跃超过一天后再达标，连续学习从 1 重新开始。
- 连续日期只比较 `localDay` 的公历相邻关系；实现用年、月、日做 UTC 日历运算，不用两个本地午夜之间是否恰好相差 24 小时判断，避免夏令时误断。
- 本设计信任浏览器提供的本地日期，不引入网络授时或位置权限。

## 8. 错题本

### 8.1 收录与移出

错题本不新增持久化集合，而从 `questionStats` 派生：

- 每题最近一次自评为 `hard` 或 `fuzzy` 时自动收录。
- 最近一次自评为 `mastered` 时立即移出。
- 同一题只有一个条目，标签显示其最近状态“不会”或“模糊”。
- 以后再次评为不会 / 模糊时可重新进入。
- 按 `J` 手动加入或移出待复习只改变复习成员和调度，不伪造最近自评，因此不直接改变错题本。

现有累计 `hardCount`、`fuzzyCount`、`masteredCount` 可继续用于统计，但错题本不展示或保存评级事件时间线。已经掌握并移出的题不保留“曾在错题本”的归档。

### 8.2 浏览列表

- 列表按 `lastReviewedAt` 从新到旧排序，相同时间按题目 ID 升序。
- 每项显示当前题目文本、不会 / 模糊标签和“去练习”按钮。
- 题目文本运行时从 `questionsById` 取得，不复制进状态或导出文件。
- 列表最多受当前题库题数限制；在对话框内自然滚动，不新增分页或搜索。
- 空状态文案为“错题本是空的，继续保持”。

### 8.3 “去练习”与现有复习流

点击某条“去练习”：

1. 若题目已在 `hardIds` / `views.hard.deck`，直接把 hard 视图索引定位到该题。
2. 若用户曾用 `J` 手动移出，按现有手动加入待复习语义重新加入，再定位到该题。
3. 切换现有 `mode` 为 `hard`，不创建第三种训练模式或独立题序。
4. 关闭学习记录对话框。
5. 隐藏答案和评级，焦点移到该题标题。

在这条复习流中把题评为掌握后，现有逻辑负责从 `hardIds` 和 `reviewQueue` 移出，同时最新题目统计使它从错题本消失。

### 8.4 与复习队列的区别

- 错题本回答“哪些题最近仍不会或模糊”，是当前状态的浏览视图。
- `hardIds` 回答“哪些题属于待复习模式”，同时允许用户手动增删。
- `reviewQueue` 回答“哪道题在第几次后续自评后自动插入”，是调度数据。
- 三者不互相复制。错题本由 `questionStats` 派生，“去练习”只是进入现有 hard 流程。

## 9. 组件边界与数据流

### 9.2 `assets/styles.css`

### 9.4 自评数据流

`评级按钮 / 快捷键`
→ `applyRating` 使用单一时间快照
→ XP / 题目统计 / 复习调度
→ `updateActivityDay`
→ 生成完整 v3 新状态
→ 单次 `localStorage.setItem`

## 10. 本地状态与迁移

### 10.1 版本选择

由于 v2 的活动桶只有每日总自评数，无法证明“20 道不同题”，实现必须升级为：

```text
STATE_VERSION = 3
STORAGE_KEY = go-interview-progress-v3
PREVIOUS_STORAGE_KEY = go-interview-progress-v2
LEGACY_STORAGE_KEY = go-interview-progress-v1
```

这不是可选字段兼容变更。继续把新结构写成 v2 会让旧导入文件被错误当成能够证明不同题数。

### 10.2 最小新增源数据

除版本号外，唯一新增的业务源数据位于每个活动日桶：

```json
{
  "version": 3,
  "activityDays": [
    {
      "localDay": "2026-08-10",
      "dayStartedAt": "2026-08-09T15:00:00.000Z",
      "ratingCount": 4,
      "ratedQuestionIds": [3, 7, 12]
    }
  ]
}
```

这是状态片段，不是完整导入文件。字段语义：

- `localDay`：活动桶的权威身份，使用发生自评时的浏览器本地日期。
- `dayStartedAt`：首次创建该桶时，本地午夜对应的 ISO 8601 UTC 时间；保留兼容与诊断用途，不再作为跨时区身份。
- `ratingCount`：当天全部有效自评次数，重复题也增加。
- `ratedQuestionIds`：当天至少自评过一次的题目 ID，唯一、升序、只含当前题库合法 ID。

以下数据均派生，不持久化：

- 当前心情。
- 今日是否打卡成功及 `N / 20`。
- 日历单元格状态和当前可导航月份。
- 错题本条目。
- 打卡成功提示是否可见。

### 10.3 活动桶约束与 400 日上限

- 每个 `localDay` 最多一个活动桶。
- `localDay` 必须是可解析的真实公历日期，不能只做正则匹配。
- `dayStartedAt` 必须是规范 ISO 8601 UTC 字符串。
- `ratingCount` 是正整数，且必须 `>= ratedQuestionIds.length`。
- `ratedQuestionIds` 不能重复，必须存在于当前题库。
- 数组按 `localDay` 升序保存，保证导出确定性。
- 只保留最近 400 个非空本地日桶；第 401 个加入后删除最早桶。
- 单桶保存所有不同题 ID，不在 20 个时截断。当前题库只有 100 个 ID，完整保存可避免题目后续移除时失去替补证据。
- 裁剪活动桶不重算或降低已保存的 `longestStudyStreakDays` 汇总。

### 10.4 v2 → v3 迁移

加载优先级：

1. v3 存在时只校验 v3；无效则安全重置并警告，不回退到可能过期的 v2。
2. v3 不存在时读取并完整校验 v2。
3. v2 不存在时才尝试现有 v1；有效 v1 先形成现有训练状态，再补成 v3。
4. 高优先级状态存在但损坏时，不读取更旧状态拼接修复。

有效 v2 迁移时：

- 保留模式、完整题序、两个导航视图、最近访问历史、`hardIds`、`reviewQueue`、全局 `ratingCount`、轮次、总 XP、连续掌握、`lastPracticeAt` 和 `questionStats`。
- 每个旧活动桶保留 `dayStartedAt` 与 `ratingCount`。
- 在迁移发生时的浏览器时区中，把旧 `dayStartedAt` 映射成一次性的 `localDay`。
- 若多个旧桶映射到同一 `localDay`，合并 `ratingCount`，保留最早 `dayStartedAt`。
- 旧状态没有每日题目 ID 证据，因此 `ratedQuestionIds` 初始化为空，不根据当前 `questionStats` 猜测。
- 旧活动日在日历中可显示“有训练，未验证”，但不能显示已打卡。
- `studyStreakDays` 与 `longestStudyStreakDays` 从 0 重新开始；旧 10 次阈值形成的连续记录不能冒充新规则资格。
- “坚持一周”仍由 `longestStudyStreakDays >= 7` 派生，因此迁移后会暂时重新锁定，直到按新规则完成连续 7 天；不新增独立成就解锁字段。
- 首次迁移显示一次非阻断说明：“打卡规则已升级为每天 20 道不同题；训练与 XP 已保留，连续打卡从新规则重新计算。”
- 成功写入 v3 后保留 v2 键一个版本周期，便于代码回滚；后续训练只更新 v3。

因此，若用户在迁移当天已经完成旧规则训练，迁移后仍需在 v3 中实际记录 20 个不同题 ID 才能完成当天新打卡。该行为是数据不可证明时的保守选择。

### 10.5 v1 → v3 迁移

- 继续保留有效 v1 的模式、题序、当前位置和不会题。
- XP、题目统计、活动桶和复习调度按现有迁移规则初始化。
- 新增的 v3 活动桶为空，连续打卡为 0。
- 不把旧不会题标成掌握，也不伪造每日题目 ID。

## 11. 导出、导入与隐私

### 11.1 导出

- 新导出信封使用 `schemaVersion: 3`、规范 UTC `exportedAt` 和完整 v3 `data`。
- 文件继续使用本地 Blob、系统分享或下载，不上传。
- 导出只包含题目 ID、训练状态、计数和 UTC 时间。
- 严禁包含 `question`、`promptHtml`、`answerHtml`、来源正文、自由文本、姓名、邮箱、设备标识、IP、精确位置、用户代理或时区名称。
- `localDay` 是训练分桶键，不附加地点或时区字符串。

### 11.2 导入

- 文件上限保持 1MB，只接受 JSON 文本。
- v3 导入必须完整校验信封、状态版本、枚举、题序、索引、计数一致性、规范时间、真实 `localDay`、400 日上限和每日 ID 唯一性。
- `ratedQuestionIds` 中每个 ID 必须存在于当前题库，`ratingCount` 必须不小于其长度。
- `activityDays` 中 `localDay` 不得重复且必须升序。
- 保留范围内每日 `ratingCount` 之和不得大于全局 `ratingCount`；题目统计尝试数、总 XP、轮次统计与全局计数继续满足现有一致性约束。
- 未识别字段只在重建白名单状态时被丢弃，任何字符串都不作为 HTML 或代码执行。
- 合法 v2 导出可在一个兼容周期内通过同一保守迁移导入；确认文案必须明确旧连续打卡会按新规则清零。
- v1、未来未知版本、损坏状态、超大文件和含非法题目 ID 的文件拒绝导入。
- 校验和迁移都在临时对象中完成；只有用户确认后才一次性替换内存和 v3 存储。
- 取消、读取失败或校验失败不得改变当前状态。
- 不自动合并两个设备的每日 ID 集合，避免 XP、题目统计和连续天数重复。

## 12. 异常与降级

- **`localStorage` 不可访问**：应用以内存状态继续；当次页面内仍可累计 20 个不同题并显示成功，但刷新后丢失。持续显示非阻断警告和可用的导出入口。
- **持久化失败**：保留完整内存状态，不撤销刚完成的 XP 或打卡 UI；提示立即导出。后续每次状态写入可继续尝试。
- **v3 损坏**：安全创建新 v3，不拼接 v2；提示本地进度无效。
- **v2 迁移写入失败**：当前会话使用迁移后的内存状态，但不删除 v2；提示无法保存，避免破坏回滚数据。
- **系统时间无效**：本次评级仍可按现有 XP / 复习规则处理，但不写入活动桶、不更新连续打卡，并提示系统日期不可用。
- **时钟在会话中跳变**：每次评级重新捕获时间；心情在焦点 / 可见性恢复时纠正，不依赖旧计时器推算。
- **题库 ID 被移除**：本地加载时过滤活动桶、错题本、hard 视图和队列中的失效 ID，并警告；若每日证明降到 20 以下，日历按剩余证据降级。导入则直接拒绝失效 ID，不静默改写文件。
- **题库为空或结构无效**：停止训练并使用现有紧急错误状态；学习记录不得允许改写状态。
- **原生对话框不可用**：使用受控页面内面板降级，不请求 polyfill。
- **Service Worker 失败**：普通 HTTPS 静态站点和 `file://` 刷题继续可用。
- **吉祥物视觉样式未加载**：状态文字、`N / 20` 和成功文案仍是权威反馈。

## 13. 响应式、无障碍与动效

### 13.1 响应式

- 320px 宽度无横向页面溢出。
- 头部允许分行；“学习记录”占用原分类槽位，不新增挤压项。

- 错题项在窄屏把“去练习”按钮放到题目下方。
- 对话框宽度不超过视口，内部长列表自然滚动。
- 所有操作目标至少 44×44 CSS 像素。

### 13.2 无障碍

- 吉祥物状态始终有可见文字，不依赖表情图形解释。
- 今日进度使用原生文本和 ARIA progressbar 属性。
- “今天”使用 `aria-current="date"`；日期格可访问名称包含完整日期、状态和进度。
- 已打卡、部分、错过、未来同时使用文字 / 图形与颜色。

- 学习记录标签遵守标签键盘模型；关闭恢复焦点。
- “去练习”按钮名称包含题目序号或简短题目文本，不能全部只读成“去练习”。
- 快捷键继续忽略按钮、输入、可编辑区域和带修饰键组合。
- 新对话框打开时暂停全局刷题快捷键，避免按数字切换标签时误评级。

### 13.3 Reduced motion

- `prefers-reduced-motion: reduce` 时取消吉祥物抖动、汗滴动画、进度条缓动和对话框弹入。
- 普通模式可使用极短的非循环状态过渡，但不得持续晃动或闪烁。
- 心情和成功状态必须在无动画时同样清晰。
- 评级后的 300ms 视觉等待按现有规则取消，但状态保存和直播播报不能取消。

## 14. 离线、`file://` 与 PWA 缓存

- 所有新 UI 和状态逻辑位于现有 `index.html`、`assets/styles.css`、`assets/app.js`，不增加运行时网络访问。
- `file://` 继续用普通脚本、题库和本地存储完整支持打卡、日历、错题本及导入导出。
- `file://` 不注册 Service Worker、不显示原生安装入口。
- HTTPS / localhost PWA 在首次在线缓存后离线提供相同行为。
- 吉祥物是 `index.html` 内联 SVG 加 CSS 状态类，不新增应用壳资源路径。
- 实现修改了已缓存的 HTML、CSS、JavaScript，因此必须提升 `service-worker.js` 的 `CACHE_NAME`。
- `APP_SHELL` 清单内容保持现有受控文件；manifest 和安装图标条目不变。
- 更新继续使用等待状态和用户主动“保存并更新”，不得在答题或 300ms 反馈期间强制刷新。

- 题卡仍位于主要内容层级，日历 / 错题本只在二级对话框。
- 三种主反馈文案逐字匹配本设计，XP / 调度为次级。
- 第 20 题在自动前进前更新头部成功状态。
- 非 reduced-motion 保留约 300ms；reduced-motion 立即前进。
- 每次评级只有一条完整礼貌播报。
- 标签、月份导航、关闭和“去练习”可全键盘完成并恢复焦点。
- 320px 不横向溢出，触控目标不小于 44px。

### 17.6 导入导出与离线

- v3 导出不含题目正文、HTML、来源正文或 PII。
- 合法 v3 导入覆盖；非法日期、重复每日 ID、未知题目 ID、401 个活动桶、超大或未知版本拒绝。
- 合法 v2 导入先告知新规则清零影响，再经确认迁移。
- 校验失败和取消不写本机状态。
- 存储拒绝时内存打卡仍可完成并明确警告。
- `file://` 完整支持功能且不注册 Service Worker。
- manifest 和安装图标字节不因应用内心情变化而改变。
- PWA 缓存版本提升后，首次在线加载再断网仍可打开全部功能。

## 18. 验收标准

1. 任一本地日只有完成 20 个不同题 ID 的有效自评才显示已打卡并获得连续学习资格。
2. 重复自评照常结算 XP / 调度，但不重复增加 `N / 20`；揭晓和跳过完全不计。
3. 未完成时在 `[00:00,15:00)`、`[15:00,21:00)`、`[21:00,24:00)` 分别显示普通、焦虑、抓狂。
4. 达到 `20 / 20` 的同一状态事务内显示普通吉祥物与“今日打卡成功”。
5. PWA 系统安装图标及 manifest 图标声明保持固定，不随心情或进度变化。
6. 三种评级显示批准的鼓励主文案，XP / 复习信息为次级，并保留 300ms / reduced-motion 与单次直播播报。
7. 学习记录入口占用原禁用分类槽位；日历和错题本只作为二级面板，题目卡仍是首要工作区。
8. 日历可按月前后导航，并正确区分已打卡、部分、错过、未来和今天。
9. 旅行或时钟回拨不重标历史 `localDay`，不减少 XP，不重复增加连续学习。
10. 错题本由最近 hard / fuzzy 派生，mastered 移出；“去练习”复用现有 hard 模式。
11. v3 每日桶保存可验证的唯一题目 ID，最多保留 400 个非空本地日。
12. v2 训练、XP、题目统计和复习状态被保守迁移；无法证明的旧活动不冒充新打卡。
13. v3 导出不含题目内容或 PII，导入在确认前不改变任何状态。
14. 320px、纯键盘、读屏、reduced-motion、离线 PWA 和 `file://` 均可完成核心流程。
15. 实现不修改题目生成数据、安装图标，不增加外部资源、后端或新依赖。

## 19. 风险与取舍

- **迁移会重置连续打卡**：v2 无法证明不同题，保留旧连续值会违反新规则；本设计选择数据诚实，并保留 XP 与训练进度。
- **本地时钟可被用户修改**：无后端时无法权威校时；使用固化 `localDay` 和单调连续更新限制重复收益，但不宣称防作弊。
- **错过状态是推断**：活动桶只记录有自评的日期，因此仅在保留历史范围内推断错过，范围外明确显示无数据。
- **每日 ID 增加存储体积**：上限为 400 天 × 当前 100 个整数 ID，仍显著低于 1MB 导入上限；严格裁剪防止无限增长。
- **单一学习记录对话框多一层操作**：换取头部不拥挤和题卡专注，符合 Sprint Companion 方向。
- **吉祥物只用内联 SVG 绘制**：换取零外部素材、无缓存新增项和 `file://` 一致性；状态文字保证语义不依赖绘制质量。

## 20. 明确排除项

- 动态系统图标、动态 favicon、PWA badge、桌面小组件。
- 推送通知、每日提醒、后台定时任务或系统日历集成。
- 服务器时间、位置权限、旅行自动修复或防作弊机制。
- 错题笔记、富文本、标签、收藏夹、搜索、导出单独错题集。
- 错题历史时间线、掌握归档或评级事件日志。
- 新分类元数据、按分类训练或修改题库生成链路。
- 日历日期详情页、补签、手动改状态或社交分享打卡。
- 新主页面、路由、仪表盘、排行榜、账号和云同步。
- 修改 XP、等级、成就门槛、复习间隔或基础轮次算法。
