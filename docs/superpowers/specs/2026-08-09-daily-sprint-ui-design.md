# Golang Interview 每日闯关冲刺 UI 设计

## 1. 背景与现状

当前页面采用单张题卡、显示答案、前后切题和“不会题”标记的基础结构。它可以离线运行，也具备键盘操作和本地进度保存，但视觉层级与操作反馈偏弱，用户难以感受到连续训练、答题结算和成长过程。

本次改版选择 B「每日闯关冲刺」中的 B1「单卡快刷」方向。改版继续使用纯 HTML、CSS 和 JavaScript，保留 `file://` 与 GitHub Pages 部署能力，不增加 Go 后端、构建工具、第三方依赖或运行时网络请求。

## 2. 目标与非目标

### 2.1 目标

- 打开页面后直接进入无限随机刷题，不增加训练配置步骤。
- 建立“主动回忆 → 揭晓答案 → 三级自评 → 自动下一题”的稳定节奏。
- 使用 XP、等级、连续学习天数和连续掌握数提供真实成长反馈。
- 将闯关数据持久化到版本化 `localStorage`。
- 支持在 GitHub Pages HTTPS 环境中安装为 PWA，并在安装后离线刷题。
- 支持进度 JSON 导出和导入，降低清理浏览器或更换设备导致的数据丢失风险。
- 保留现有不会题、前后导航、重新洗牌、来源徽标、空状态、键盘、无障碍、离线和异常降级能力。

### 2.2 非目标

- 不增加账号、云同步、排行榜或多人功能。
- 不在设备之间自动同步或自动合并进度。
- 不执行用户输入的 Go 代码。
- 不在本次改版中为 100 道题补充分类元数据。
- 不修改题目正文、参考答案或来源标签。
- 不引入框架、CDN、远程字体、远程图片、`fetch` 或 ES module。

分类入口在界面中显示为不可操作的“分类即将上线”，并提供明确说明；在题库完成分类元数据前，不提供空筛选或伪分类结果。

## 3. 核心训练流程

### 3.1 进入页面

1. 加载并校验题库。
2. 读取 v2 本地状态；不存在时尝试迁移 v1。
3. 恢复当前题目、题序、待复习队列和闯关数据。
4. 若没有可恢复状态，则生成包含全部 100 道题的随机轮次。
5. 默认隐藏参考答案，并把焦点保持在题目区域和主要操作之间的合理顺序。

### 3.2 主动作答

1. 页面一次只展示一道题。
2. 用户先口述或思考答案。
3. 点击“揭晓参考答案”或按空格后显示答案。
4. 答案揭晓前不显示三级自评，防止用户跳过主动回忆。
5. 答案揭晓后显示“不会 / 模糊 / 掌握”三个自评按钮。
6. 用户完成自评后立即结算数据、保存状态并切换下一题。

默认保留 300ms 的 XP 反馈时间；系统开启 reduced motion 时不等待动画，直接进入下一题。

### 3.3 无限轮次

- 基础题序始终是 1–100 的完整随机排列，轮内每个唯一题号至少出现一次。
- 待复习题通过独立调度队列插入，不向基础题序写入重复 ID。
- 完成 100 道唯一题后展示非阻断的本轮摘要。
- 摘要显示掌握、模糊、不会和本轮获得 XP，不要求用户确认。
- 系统随后自动洗牌并进入下一轮，保持无限刷题。
- 尚未到期的待复习调度项保留到下一轮，使用全局累计自评次数判断到期。

### 3.4 导航、待复习与洗牌

- `history` 记录实际展示过的题号，包含由待复习调度产生的重复题。
- 上一题和下一题优先在已访问历史中移动；位于历史末尾时，下一题才从到期待复习项或基础题序生成。
- 用户通过下一题跳过未自评题目时不获得 XP，也不修改该题掌握统计。
- “待复习”模式使用 `hardIds` 的独立随机视图；两个模式各自保存导航位置，切回“随机刷题”时恢复原轮次位置。
- 在待复习模式选择“掌握”会移除当前题；移除最后一道题后显示现有空状态。
- 按 `J` 手动加入待复习时创建 7 次后到期的调度项；手动移除时同步删除该题调度项，但不改写历史自评记录。
- 手动重新洗牌会开始新的基础轮次，但保留 XP、题目统计、连续记录和待复习项。
- 已访问历史只保留最近 200 个题号，避免无限刷题导致本地状态持续增长。

## 4. 自评、XP 与复习规则

### 4.1 三级自评

- **不会**：获得 2 XP，加入待复习，在完成 7 次后续作答后再次出现。
- **模糊**：获得 8 XP，保留在待复习，在完成 20 次后续作答后再次出现。
- **掌握**：获得 20 XP，从待复习中移除，本轮不再主动重复。

若同一道待复习题再次被评为不会或模糊，旧调度记录被新记录替换，保证一个题号最多存在一个待复习调度项。

### 4.2 XP 与等级

- 每次自评都结算 XP，包括同一道题的重复练习。
- XP 表示练习投入，不等同于知识掌握率。
- 掌握率依据每题最近一次自评和累计自评记录单独计算。
- 等级由总 XP 派生，不重复持久化。
- 每 `XP_PER_LEVEL` XP 提升一级：`level = floor(totalXp / XP_PER_LEVEL) + 1`。门槛 2026-08-11 起由 1000 调整为 20，使一道「掌握」即可升级。
- 等级进度显示当前等级区间内的 XP，不把重复练习包装成掌握增长。

### 4.3 两种连续记录

- **连续掌握数**：连续选择“掌握”时递增；选择“不会”或“模糊”时归零。
- **连续学习天数**：用户在一个浏览器本地自然日内完成至少 10 次自评后，该日记为有效学习日。

所有事件时间保存为 ISO 8601 UTC。界面展示和自然日判断使用浏览器当前时区；导出数据中不保存本地时间字符串。

### 4.4 基础成就

首版成就全部由闯关源数据派生，不保存独立解锁状态：

- **初次出发**：完成第一次自评。
- **百题热身**：累计完成 100 次自评。
- **完整一轮**：完成一次包含全部 100 道唯一题的轮次。
- **坚持一周**：最长连续学习天数达到 7 天。
- **渐入佳境**：最近自评为“掌握”的唯一题目达到 50 道。

## 5. 界面设计

### 5.1 顶部区域

顶部保持紧凑，包含：

- Go 冲刺营品牌。
- 当前等级。
- 总 XP 的等级进度条。
- 连续学习天数。
- 当日已完成题数。
- “随机刷题”“待复习”“成就”三个入口。

“成就”只展示由已有数据可确定计算的基础成就，不建立独立可变状态。分类入口显示“分类即将上线”并使用 `aria-disabled="true"`。

### 5.2 题目卡片

题目卡片依次包含：

- 本轮题号和当前唯一题进度。
- 现有“补充整理”来源徽标。
- 题目文本。
- 主动回忆提示。
- 隐藏或展开的参考答案。
- 当前阶段唯一的主要操作。

答案隐藏时，主要操作是“揭晓参考答案”；答案显示后，主要操作变为三级自评。上一题、跳过和加入待复习保持次级视觉权重。

### 5.3 反馈

- 自评后在原按钮附近显示本次 XP 增量。
- 等级提升时显示一次非阻断庆祝反馈。
- 连续学习达标时显示“今日训练已完成”。
- 所有动画都遵守 `prefers-reduced-motion`。
- 不使用遮挡题目的长时间弹窗，不要求重复确认。

### 5.4 响应式与无障碍

- 320px 宽度下不得横向溢出。
- 触控目标不小于 44px。
- DOM 顺序与移动端视觉顺序一致。
- 题目、答案、自评状态和 XP 反馈提供合适的 ARIA 状态。
- 空格负责揭晓答案，数字 `1 / 2 / 3` 对应不会、模糊、掌握。
- 方向键继续用于前后切题，`J` 继续切换待复习标记。
- 输入控件、可编辑区域和带修饰键的组合操作不得触发快捷键。

### 5.5 安装与进度管理

- 在支持 `beforeinstallprompt` 的浏览器中显示“安装应用”按钮，并只在用户主动点击后触发安装提示。
- iPhone、iPad 和不提供安装事件的浏览器显示对应的“添加到主屏幕”操作说明，不伪造系统安装状态。
- 应用处于 standalone 模式时隐藏安装入口。
- 进度管理面板提供“导出进度”“导入进度”和“重置进度”。
- 支持 Web Share API 且允许分享文件时，导出后优先调用系统分享；否则下载 JSON 文件。
- 导入使用标准文件选择控件，保证移动端与桌面端均可使用。

## 6. 本地状态设计

### 6.1 存储键与版本

新状态使用：

```text
go-interview-progress-v2
```

状态对象只保存恢复与计算所需的源数据。等级、掌握率和成就等可派生值不写入存储。

### 6.2 状态结构


实际 `deck` 必须包含 1–100 的完整唯一排列。示例为缩略展示，不代表可通过校验的完整持久化数据。

`views.hard.deck` 在加载和 `hardIds` 变化后重新规范化，只允许包含当前待复习题号且不得重复。`activityDays` 只保留最近 400 个自然日桶；最长连续天数作为汇总值保留。

### 6.3 写入时机

以下操作后同步写入完整状态：

- 三级自评。
- 手动切题、快捷键导航或切换待复习模式。
- 重新洗牌。
- 新轮次开始。
- 导入数据成功。
- 重置进度。

写入前先在内存中生成完整新状态，再进行单次 `setItem`，避免分字段写入造成半完成状态。

## 7. v1 迁移

迁移流程：

1. 优先读取并校验 v2。
2. v2 不存在时读取 `go-interview-progress-v1`。
3. 保留 v1 的 `mode`、`deck`、`index` 和 `hardIds`。
4. 初始化 XP、活动日、题目统计和复习队列。
5. 将当前 v1 位置对应的题号写入 `views.all.currentQuestionId`，并创建只含当前题目的导航历史。
6. 成功写入 v2 后继续保留 v1 一个版本周期，便于回滚。
7. v1 无效时创建全新 v2 状态，不尝试猜测或部分修复。

迁移不得把旧“不会题”静默标记为已掌握。

## 8. 导出、导入与重置

### 8.1 导出

- 使用浏览器 `Blob` 和本地下载能力生成 JSON 文件。
- 导出对象包含 `schemaVersion`、`exportedAt` 和完整 v2 数据。
- `exportedAt` 使用 ISO 8601 UTC。
- 文件不包含题目答案、浏览器信息、个人信息或远程地址。

### 8.2 导入

- 只接受 JSON 文件。
- 文件大小上限为 1MB。
- 必须完整校验版本、字段类型、有限枚举、题号范围、题序唯一性和时间格式。
- 未识别字段被忽略，不执行任何字符串内容。
- 校验失败时不修改当前内存或 `localStorage`。
- 校验成功后先请求用户确认，再一次性覆盖并重新渲染。

### 8.3 重置

重置操作必须二次确认，并明确说明会清除 XP、等级进度、连续天数、题目统计和待复习记录。取消确认时不得修改任何状态。

## 9. PWA 安装与离线缓存

### 9.1 Manifest

新增根目录 `manifest.webmanifest`，使用相对路径保证 GitHub Pages 子路径部署：

- `name`：`Go 面试冲刺营`。
- `short_name`：`Go 冲刺营`。
- `start_url`：`./`。
- `scope`：`./`。
- `display`：`standalone`。
- `theme_color` 与 `background_color` 使用 B1 主题色。
- 提供本地 192×192、512×512 和 maskable 图标，不引用远程资源。

`index.html` 增加 manifest、主题色、Apple Touch Icon 和必要的 PWA 元数据。

### 9.2 Service Worker

新增根目录 `service-worker.js`：

- 安装阶段预缓存 `index.html`、样式、脚本、题库、manifest 和本地图标。
- 只处理同源 GET 请求，不拦截或缓存第三方地址。
- 页面导航使用 network-first，离线时回退到缓存的 `index.html`。
- 带版本的静态资源使用 cache-first；缓存未命中时才访问同源文件。
- activate 阶段删除旧版本缓存。
- 缓存升级后通知页面存在新版本，由用户确认后刷新，不在答题过程中强制重载。

Service Worker 使用相对 URL 和当前 scope，不硬编码仓库名、生产域名或 GitHub Pages 地址。

### 9.3 协议兼容

- 仅在 `https:` 或 `http://localhost` 且浏览器支持 Service Worker 时注册。
- `file://` 环境跳过注册和安装入口，原有普通脚本加载、题库和 `localStorage` 刷题能力继续工作。
- 首次 PWA 安装必须在线完成；成功缓存后才能保证离线启动。
- PWA 安装不改变进度存储位置，每个浏览器配置仍拥有独立 `localStorage`。

### 9.4 多设备进度转移

多端安装不等于云同步。设备间转移使用：

1. 源设备导出 v2 JSON。
2. 通过系统分享、文件或用户选择的渠道传到目标设备。
3. 目标设备选择导入。
4. 完整校验通过后提示将覆盖本机进度。
5. 用户确认后一次性替换本机状态。

首版不提供自动合并，避免重复累计 XP、连续天数冲突和题目统计失真。

## 10. 异常与边界处理

- `localStorage` 不可访问：以内存状态运行，并持续显示非阻断警告。
- 写入超限或失败：保留当前内存状态，提示用户立即导出进度。
- v2 JSON 损坏：不使用损坏字段；尝试 v1 迁移，仍失败则安全重置。
- 导入文件无效：展示具体的非敏感错误原因，不覆盖当前状态。
- 题库 ID 变化：过滤不存在的题目统计和待复习项，再为当前题库生成有效题序。
- 系统时间回拨：不减少已获得 XP；连续学习天数只在出现新的有效自然日时递增。
- 待复习题被移出题库：加载时删除对应调度和统计引用。
- 题库为空或结构无效：停止刷题操作并显示现有紧急错误状态。
- Service Worker 注册失败：不阻断页面，退化为普通 GitHub Pages 静态站点。
- 预缓存失败：安装阶段失败且不接管页面，避免产生不完整离线版本。
- 新版本等待激活：保留当前答题状态并显示更新提示，由用户主动刷新。

## 11. 文件影响

- `index.html`：增加闯关状态、三级自评、待复习入口和进度管理面板。
- `assets/styles.css`：实现 B1 视觉、状态反馈、响应式和 reduced motion。
- `assets/app.js`：实现 v2 状态、迁移、游戏规则、调度、导入导出和 DOM 行为。
- `manifest.webmanifest`：定义 PWA 安装信息和本地图标。
- `service-worker.js`：实现同源应用壳预缓存、离线回退和版本更新。
- `assets/icons/`：保存 PWA 192、512 和 maskable 图标。
- `tests/test_app.js`：覆盖状态和交互行为。
- `scripts/verify_project.py` 与对应测试：验证 manifest、Service Worker、本地资源、同源缓存边界，并区分允许的 Service Worker 请求拦截与禁止的远程运行时依赖。
- `README.md`、`AGENTS.md` 和 `docs/AI-MAINTENANCE.md`：同步新的状态版本、快捷键和维护约束。

`data/questions.js`、提取器和构建器不在本次修改范围内。

## 12. 测试与验收

### 12.1 自动测试

先写失败测试并确认 RED，再实现：

- v1 有效状态迁移到 v2。
- v1/v2 损坏状态安全恢复。
- 不会、模糊、掌握分别结算 2/8/20 XP。
- 重复题每次自评都结算 XP。
- 不会题在 7 次后续作答后到期。
- 模糊题在 20 次后续作答后到期。
- 同一题只有一个待复习调度项。
- 前后导航复用已访问历史，不重复消耗基础题序。
- 下一题跳过未自评题目时不结算 XP。
- 手动加入或移除待复习同步维护调度项。
- 待复习模式移除最后一道题后显示空状态。
- 随机刷题与待复习模式分别恢复各自导航位置。
- 重新洗牌保留闯关和待复习数据。
- 连续掌握数递增和归零。

## 13. 风险与后续

- 每次重复练习都获得 XP，用户可以通过重复题快速升级。该行为已明确接受，因此 XP 只表达练习投入，掌握率必须独立展示。
- `localStorage` 属于单浏览器数据，仍可能因清理站点数据或设备损坏丢失；导出/导入降低风险，但不等同于云同步。
- 浏览器时区变化可能影响自然日边界；时间源保持 UTC，连续学习按当前浏览器时区解释。
- 分类筛选必须等题库具有受控分类元数据后再启用，不能依靠关键词猜测分类。
- PWA 安装入口受浏览器和系统策略控制，无法保证所有平台显示同一种原生安装提示。
- Service Worker 会引入缓存版本管理；遗漏缓存版本更新可能让用户短期看到旧资源，因此每次应用壳变更都必须同步提升缓存版本。
- 若后续增加云同步，需要设计独立的数据合并和冲突策略，不复用本地覆盖导入逻辑。
